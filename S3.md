# S3 Gateway — pakai MEGA seperti AWS S3

Gateway ini membuat akun MEGA-mu bisa diakses lewat **protokol S3 asli** (AWS Signature V4).
Artinya kode yang biasanya pakai `@aws-sdk/client-s3`, boto3, rclone, Laravel Flysystem, atau
`aws s3 cp` bisa langsung dipakai — cukup arahkan endpoint ke server ini. **Data tetap disimpan di MEGA.**

```
Aplikasi kamu  ──S3 protocol──>  mega-drive S3 gateway  ──megajs──>  MEGA Cloud Drive
```

---

## 0. Quick start (5 menit)

**Langkah 1 — buat `s3-identities.local.json`** di root project (salin dari `s3-identities.example.json`):

```json
{
  "identities": [
    {
      "name": "aplikasi",
      "accessKeyId": "MEGADRIVEAPLIKASI0001",
      "secretAccessKey": "ganti-dengan-rahasia-panjang-acak"
    }
  ]
}
```

Setiap identitas mendapat ruang sendiri di MEGA (`s3/aplikasi/`), terpisah dari identitas lain.
Boleh lebih dari satu entri — lihat [bagian 1b](#1b-identitas--isolasi-data).

> Malas bikin file? Cukup isi `S3_ACCESS_KEY_ID` dan `S3_SECRET_ACCESS_KEY` di `env.local`
> seperti dulu; gateway membuat satu identitas `default` dari situ.

**Langkah 2 — jalankan gateway:**

```bash
bun run s3
```

Muncul `mega-drive S3 gateway jalan di http://0.0.0.0:3001` beserta daftar identitas.

**Langkah 3 — arahkan aplikasimu ke sana:**

```js
const s3 = new S3Client({
  endpoint: 'http://localhost:3001',
  region: 'us-east-1',
  credentials: { accessKeyId: 'MEGADRIVEAPLIKASI0001', secretAccessKey: 'ganti-dengan-rahasia-panjang-acak' },
  forcePathStyle: true,
})
```

**Langkah 4 — pakai seperti S3 biasa:**

```js
await s3.send(new PutObjectCommand({
  Bucket: 'gambar',              // → folder "gambar" di dalam ruang identitas
  Key: 'produk/sepatu.png',      // → s3/aplikasi/gambar/produk/sepatu.png di MEGA
  Body: buffer,
  ContentType: 'image/png',
}))
```

Selesai. Bucket `gambar` otomatis dibuat. File benar-benar tersimpan di MEGA-mu —
kalau gateway dimatikan dan kamu buka MEGA, file itu ada di
`s3/aplikasi/gambar/produk/sepatu.png`.

> REST API di port 3000 tetap jalan seperti sebelumnya. Keduanya memakai akun MEGA yang sama,
> jadi file yang di-upload lewat S3 bisa dilihat lewat REST API, dan sebaliknya.

## 1. Konfigurasi

Ada dua hal yang dikonfigurasi: **siapa yang boleh masuk** (identitas) dan **bagaimana server jalan**.

### 1a. Variabel server

Tambahkan ke `env.local` (lihat `env.example`):

```dotenv
S3_PORT=3001
S3_REGION=us-east-1
```

| Variabel | Default | Keterangan |
|---|---|---|
| `S3_PORT` | `3001` | Port gateway, dipisah dari REST API (3000) |
| `S3_HOSTNAME` | `0.0.0.0` | Alamat bind. Pakai `127.0.0.1` kalau hanya lokal |
| `S3_REGION` | `us-east-1` | Harus sama dengan region di sisi klien |
| `S3_IDENTITIES_FILE` | `s3-identities.local.json` | Nama file identitas (relatif ke root project) |
| `S3_FORCE_PATH_STYLE` | `true` | Wajib `true` untuk endpoint non-AWS |
| `S3_AUTO_CREATE_BUCKET` | `true` | Bucket baru otomatis dibuat saat pertama dipakai |
| `S3_STRICT_PART_SIZE` | `false` | `true` = tolak part < 5 MB seperti S3 asli |
| `S3_MAX_CLOCK_SKEW` | `900` | Toleransi selisih jam klien vs server (detik) |
| `S3_MAX_BODY_BYTES` | `5368709120` | Batas ukuran body request (5 GB) |
| `S3_VERIFY_MAX_BYTES` | `16777216` | Batas pengecekan `x-amz-content-sha256` (16 MB) |

`S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` hanya dipakai kalau file identitas tidak ada —
lihat bagian berikut.

### 1b. Identitas & isolasi data

Setiap identitas adalah satu pasang access key + satu ruang penyimpanan sendiri di MEGA:

```
s3-identities.local.json
  ├── "aplikasi"  (AKIA...) ──> MEGA: s3/aplikasi/   ──> bucket apa pun di dalamnya
  └── "cadangan"  (AKIB...) ──> MEGA: s3/cadangan/   ──> bucket apa pun di dalamnya
```

**Isolasinya penuh, bukan berbasis izin.** Identitas A tidak bisa melihat, membaca, menimpa,
atau menghapus apa pun milik identitas B — semuanya dibatasi ke folder root-nya masing-masing:

| Yang dicoba identitas lain | Hasil |
|---|---|
| `ListBuckets` | Hanya bucket miliknya sendiri yang muncul |
| `GetObject` / `HeadObject` objek orang lain | `404 NoSuchKey` |
| `ListObjectsV2` bucket orang lain | `404 NoSuchBucket` |
| `PutObject` ke bucket+key yang sama | Boleh — tapi menulis ke ruangnya sendiri, tidak menimpa |
| `DeleteObject` objek orang lain | `404` (tidak melakukan apa-apa) |
| `UploadPart` / `ListParts` / `AbortMultipartUpload` upload orang lain | `404 NoSuchUpload` |
| `DeleteBucket` bucket orang lain | `404`/`409`, data pemilik tetap utuh |

Sengaja dijawab `404` (bukan `403`) supaya identitas lain tidak bisa menebak-nebak
apa yang ada di akun ini.

Format file (`s3-identities.example.json`):

```json
{
  "identities": [
    {
      "name": "aplikasi",
      "accessKeyId": "MEGADRIVEAPLIKASI0001",
      "secretAccessKey": "rahasia-panjang-acak-1"
    },
    {
      "name": "cadangan",
      "accessKeyId": "MEGADRIVECADANGAN0002",
      "secretAccessKey": "rahasia-panjang-acak-2"
    }
  ]
}
```

Aturan:

- `name` — 1-64 karakter, huruf kecil/angka/`_`/`-`, diawali huruf atau angka. **Tidak boleh
  diganti setelah dipakai**, karena menjadi nama folder di MEGA (data lama tidak ikut pindah).
- `accessKeyId` — unik, dipakai klien sebagai `accessKeyId`.
- `secretAccessKey` — bebas, sebaiknya panjang dan acak (`openssl rand -hex 32`).
- File ini masuk `.gitignore`. Jangan di-commit.

Kalau file tidak ada atau kosong, gateway jatuh ke mode lama: satu identitas `default`
dari `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` di `env.local`, dengan root `s3/default/`.

> **Catatan:** isolasi ini berlaku di lapisan S3 gateway. REST API di port 3000 tidak memakai
> identitas dan tetap melihat seluruh isi akun MEGA (termasuk semua folder `s3/*`). REST API
> dirancang untuk localhost saja.

### 1c. Dua sisi konfigurasi

Ada dua tempat env var dipakai, dan ini sering bikin bingung:

| Di **server gateway** (env.local) | Di **aplikasi klien** (env aplikasimu) |
|---|---|
| `S3_PORT`, `S3_HOSTNAME` | `S3_ENDPOINT` → `http://localhost:3001` |
| `S3_REGION` (harus sama dengan klien) | `S3_REGION` |
| `S3_IDENTITIES_FILE` | `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` (salah satu identitas) |
| `S3_FORCE_PATH_STYLE`, `S3_AUTO_CREATE_BUCKET` | `S3_BUCKET` → bucket tujuan aplikasimu |
| `S3_STRICT_PART_SIZE`, `S3_MAX_CLOCK_SKEW` | `S3_FORCE_PATH_STYLE=true` |

Jadi `S3_BUCKET` **tidak** diisi di server — gateway melayani semua bucket milik identitas
yang sedang dipakai. `S3_BUCKET` adalah urusan aplikasi klien: bucket mana yang mau dipakai.

## 2. Jalankan

```bash
bun run s3        # produksi
bun run s3:dev    # auto-reload saat file berubah
```

Server jalan di `http://localhost:3001`. REST API tetap di port 3000 dan tidak terpengaruh.

## 3. Pakai dari klien

### AWS SDK v3 (JavaScript/TypeScript)

```js
import { S3Client, PutObjectCommand, GetObjectCommand } from '@aws-sdk/client-s3'

const s3 = new S3Client({
  endpoint: 'http://localhost:3001',
  region: 'us-east-1',
  credentials: {
    accessKeyId: 'MEGADRIVEAPLIKASI0001',
    secretAccessKey: 'ganti-dengan-rahasia-panjang-acak',
  },
  forcePathStyle: true,   // wajib untuk endpoint non-AWS
})

// upload gambar
await s3.send(new PutObjectCommand({
  Bucket: 'images',
  Key: 'produk/sepatu.jpg',
  Body: buffer,
  ContentType: 'image/jpeg',
}))

// ambil gambar
const res = await s3.send(new GetObjectCommand({ Bucket: 'images', Key: 'produk/sepatu.jpg' }))
```

### boto3 (Python)

```python
import boto3

s3 = boto3.client(
    "s3",
    endpoint_url="http://localhost:3001",
    region_name="us-east-1",
    aws_access_key_id="MEGADRIVEAPLIKASI0001",
    aws_secret_access_key="ganti-dengan-rahasia-panjang-acak",
    config=boto3.session.Config(s3={"addressing_style": "path"}),
)

s3.put_object(Bucket="images", Key="produk/sepatu.jpg", Body=data, ContentType="image/jpeg")
obj = s3.get_object(Bucket="images", Key="produk/sepatu.jpg")
```

### Laravel (Flysystem)

```php
// config/filesystems.php
's3' => [
    'driver' => 's3',
    'key' => env('S3_ACCESS_KEY_ID'),
    'secret' => env('S3_SECRET_ACCESS_KEY'),
    'region' => env('S3_REGION', 'us-east-1'),
    'bucket' => env('S3_BUCKET', 'images'),
    'endpoint' => env('S3_ENDPOINT', 'http://localhost:3001'),
    'use_path_style_endpoint' => true,
],
```

```php
Storage::disk('s3')->put('produk/sepatu.jpg', $contents);
Storage::disk('s3')->url('produk/sepatu.jpg');
```

### rclone

```ini
# ~/.config/rclone/rclone.conf
[mega-s3]
type = s3
provider = Other
endpoint = http://localhost:3001
access_key_id = MEGADRIVEAPLIKASI0001

```

```bash
rclone lsf mega-s3:images
rclone copy ./foto mega-s3:images/produk
```

### AWS CLI

```bash
export AWS_ACCESS_KEY_ID=MEGADRIVEAPLIKASI0001
export AWS_SECRET_ACCESS_KEY=ganti-dengan-rahasia-panjang-acak
```

## 5. Cara kerja pemetaan ke MEGA

### Root identitas dulu, baru bucket

Setiap identitas punya folder root sendiri di Cloud Drive. Bucket dibuat **di dalam** root itu:

```
s3://images/produk/sepatu.jpg          (dipakai identitas "aplikasi")
        │       │        │
        │       │        └── nama file di MEGA
        │       └─────────── subfolder
        └─────────────────── bucket → folder "images"

MEGA:  s3/aplikasi/images/produk/sepatu.jpg
       └──────────┘
       root identitas "aplikasi"
```

Jadi dua identitas boleh punya bucket bernama sama (`images`) tanpa saling bentrok — masing-masing
berada di folder root-nya sendiri. Bucket apa pun otomatis dibuat sebagai folder saat pertama
dipakai (selama `S3_AUTO_CREATE_BUCKET` tidak di-`false`).

### Key dengan "/" jadi subfolder

S3 tidak punya folder, tapi MEGA punya. Key `produk/2024/sepatu.jpg` dibuatkan folder
`produk/2024/` di dalam bucket. Saat listing, keduanya dipetakan balik jadi key datar,
jadi klien S3 tidak melihat perbedaan.

### Metadata objek disimpan di disk lokal

MEGA tidak menyimpan `Content-Type`, `Cache-Control`, atau `x-amz-meta-*`. Gateway menyimpannya
sebagai file sidecar JSON di `.s3-state/meta/`:

```
.s3-state/meta/<sha1(root identitas + bucket/key)>.json
```

Hash-nya menyertakan root identitas, jadi `aplikasi/images/a.jpg` dan `cadangan/images/a.jpg`
punya sidecar berbeda.

> **Penting:** folder `.s3-state/` (dan `.s3-tmp/`) bersifat lokal — tidak ikut ke MEGA.
> Kalau pindah mesin atau menghapus folder ini, `Content-Type` kembali ditebak dari ekstensi
> dan `x-amz-meta-*` hilang. Untuk CRUD gambar ini biasanya tidak masalah karena `.jpg`/`.png`
> tetap terdeteksi benar.

### Multipart ditampung dulu di disk

MEGA tidak punya multipart. Part disimpan di `.s3-state/uploads/<uploadId>/`, lalu digabung
dan diupload sebagai satu file saat `CompleteMultipartUpload`. Upload yang tidak pernah
diselesaikan otomatis dibersihkan setelah 24 jam (dicek saat server start).

## 6. Batasan yang perlu diketahui

- **ETag bukan MD5 konten.** MEGA tidak memberi hash MD5, jadi ETag memakai `nodeId` MEGA.
  `aws s3 sync` dan `rclone sync` tetap jalan, tapi bisa menganggap file berubah dan
  meng-upload ulang. Untuk CRUD gambar (upload → tampilkan → hapus) tidak ada masalah.
- **`Content-Type` untuk key tanpa ekstensi** jatuh ke `application/octet-stream`, kecuali
  di-set eksplisit saat upload dan sidecar metadata masih ada.
- **Update = replace.** MEGA tidak mendukung versi file di library ini, jadi menimpa objek
  membuat node baru lalu menghapus node lama. `nodeId` berubah, ETag ikut berubah.
- **Bucket dihapus permanen.** `DeleteBucket` menghapus folder MEGA langsung (bukan ke Rubbish Bin).
- **Kuota transfer MEGA** tetap berlaku. Kalau limit habis, MEGA balas `509` dan gateway
  meneruskannya sebagai `503 SlowDown`.
- **Body besar di-buffer** kalau klien tidak mengirim `Content-Length`. Kirim `Content-Length`
  (atau pakai multipart) supaya upload streaming dan hemat memori.
- **`x-amz-content-sha256`** hanya diverifikasi untuk body ≤ `S3_VERIFY_MAX_BYTES` (default 16 MB)
  agar upload besar tidak memakan memori ekstra.
- **Belum ada TLS.** Jalankan di belakang reverse proxy (Caddy/nginx) kalau mau diakses
  lewat jaringan publik — secret key dikirim sebagai bagian signature, bukan plaintext,
  tapi tetap sebaiknya pakai HTTPS.
- **Identitas tidak punya izin granular.** Semua identitas bersifat "pemilik penuh" di ruangnya
  sendiri: tidak ada read-only, tidak ada pembatasan per bucket, tidak ada IAM policy. Yang ada
  hanya pemisahan ruang antar identitas.
- **Identitas tidak bisa di-rename.** Nama identitas = nama folder di MEGA. Mengganti `name`
  membuat identitas "baru" dengan ruang kosong; data lama tetap di folder lama.

## 7. Uji

```bash
bun run s3          # di terminal 1
bun run s3:smoke    # di terminal 2 — 42 pemeriksaan protokol
bun run s3:sdk      # di terminal 2 — 9 pemeriksaan via AWS SDK resmi
bun run s3:identity # di terminal 2 — 20 pemeriksaan isolasi identitas
```

`test/s3-smoke.mjs` menandatangani request sendiri (SigV4 dari nol) dan menguji autentikasi,
CRUD, Range, metadata, listing, delimiter, copy, multipart, presigned URL, dan delete batch.
`test/s3-sdk.mjs` memakai `@aws-sdk/client-s3` asli untuk membuktikan kompatibilitas klien nyata.
`test/s3-identity.mjs` membuktikan dua identitas tidak bisa saling melihat, membaca, menimpa,
atau membatalkan multipart upload milik yang lain. Kredensial alice/bob sudah tertanam di file
itu dan cocok dengan `s3-identities.test.json`, jadi cukup arahkan `S3_ENDPOINT` ke server
yang dijalankan dengan file identitas tersebut.

Dua uji pertama membaca kredensial dari environment:

```bash
S3_ENDPOINT=http://127.0.0.1:3001 \
S3_ACCESS_KEY_ID=MEGADRIVEAPLIKASI0001 \
S3_SECRET_ACCESS_KEY=... \
bun run s3:smoke
```

Untuk uji isolasi, jalankan server dengan file identitas khusus:

```bash
S3_PORT=3101 S3_IDENTITIES_FILE=s3-identities.test.json bun run src/s3/server.js
S3_ENDPOINT=http://127.0.0.1:3101 bun run s3:identity
```

`S3_IDENTITIES_FILE` bisa menunjuk file lain, jadi pengujian tidak mengganggu
`s3-identities.local.json` yang asli.

## 8. Kode sumber

```
src/s3/
  server.js       entry point Bun.serve
  app.js          routing + handler semua operasi S3
  config.js       baca env S3_*
  identities.js   baca s3-identities.local.json (access key → root MEGA)
  sigv4.js        verifikasi AWS Signature V4 (header + presigned)
  chunked.js      decoder body aws-chunked
  store.js        pemetaan identitas+bucket/key → folder MEGA
  multipart.js    state multipart upload di disk
  object-meta.js  sidecar metadata (Content-Type, x-amz-meta-*)
  xml.js          pembentuk respons XML S3
  errors.js       kode error + status HTTP S3
```
